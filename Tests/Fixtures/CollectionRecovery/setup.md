# Synthetic collection recovery native acceptance

These are synthetic originals, not production/account data. `manifest.json` pins exact byte sizes and SHA-256 values. Copy bytes; never re-encode JSON. The legacy file has invalid interval text `-`; the future format contains opaque Unicode/newline content; the malformed file intentionally contains non-UTF-8 bytes. None may enter active editor recovery.

Controller-only setup (no product launch seeding hook):

1. Build/install the immutable reviewed source into the task-owned phone/iPad simulator. Regenerate the project to include `CollectionRecoveryUITests.swift` and the focused package test file. Existing `project.yml` includes their source directories.
2. Terminate the task app before seeding. Resolve **that simulator's** app data container for `com.fiestaboard.ios.draft` with the existing controller tooling. Create `Library/Application Support/FiestaBoard/CollectionDrafts` under that container.
3. Copy only the three files under `originals/` into that directory, with their exact filenames. Preserve existing page/collection drafts; these fixture UUIDs are dedicated. Do not copy `manifest.json` or `setup.md` into the draft store. Verify installed originals against the manifest hashes before and after the tests. Do not clear app data between seed and inventory test.
4. Run `CollectionRecoveryUITests/testSameScopeCreationDraftRecoversExactNativeInputAfterRelaunch` on each device. It uses `--demo`, edits a new collection through native text controls, keeps an invalid numeric intermediate, terminates/relaunches and explicitly recovers its own UUID-named draft. The captured exact numeric value must match after recovery. It explicitly discards only that test's recovered lineage, then checks it is no longer offered. It never sends a collection save.
5. Set **test runner** environment `COLLECTION_RECOVERY_SEEDED=1` (for xcodebuild, the controller can use `TEST_RUNNER_COLLECTION_RECOVERY_SEEDED=1` when supported by its existing runner workflow) and run `CollectionRecoveryUITests/testOriginalCollectionInventoryAndShareSheetConnectedThenDisconnected`. Without the explicit flag it skips with setup guidance; the flag itself does not seed product state. Verify the runner passes the environment before counting the test as acceptance.
6. The inventory journey opens each exact legacy/future/malformed filename, checks its classification and lack of adoption/save controls, opens the normal system share sheet, then dismisses it without choosing any activity or recipient. It repeats from the disconnected entry. Screenshots attach only synthetic app inventory/details. **Do not upload a share-sheet screenshot**, since the system can suggest personal recipients.
7. Export app-view attachments from both device results. Verify all three seeded files still match the manifest; remove only those dedicated fixture UUID files during controller cleanup if desired. Per-editor retired source bytes remain intentionally preserved; inventory is read-only.

Native APIs/flow are not claimed verified by parse/unit checks. Controller must record actual compile, test, screenshots and any platform-specific selector correction. Existing flexible tests and sources remain unchanged by this task.
