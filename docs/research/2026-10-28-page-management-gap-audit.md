## Next incremental task

Implement **create + conditional delete + refreshed library lifecycle**, retaining existing rename/edit. First extend isolated evidence for both display families and deletion's reference/replacement cases; then add strict Kit request/receipt types, session-scoped AppState mutation coordination and focused native UI. Create asks for name and explicit display geometry; show persisted acknowledgement and open its returned ID in the existing editor. Delete fetches a fresh full snapshot for review, confirms the exact page/deployment and sends that original revision once. Explain in-use409 and changed412; never silently obtain a replacement token or force deletion. Read back library/boards after an acknowledged delete, since the receipt's single replacement ID cannot describe every board's new active state.

Use per-operation capability gates and one in-flight request per management context. Keep page/editor/management writes mutually coordinated for the same ID. Capture connection generation/deployment and ignore obsolete replies after logout/switch. Transport loss, cancellation after dispatch, malformed/mismatched success, and unexpected statuses require **unknown outcome**, preserved user input and explicit readback, never automatic create/delete/import replay. Create has no idempotency key or client-chosen ID: a later matching name is not proof that this request succeeded. Offer inspection of refreshed pages; a user may explicitly start a new create after assessing duplication risk, but must not label that a retry/reconciliation success. A missing page after ambiguous deletion is observed absence, not proof this request caused it. Do not let library refresh reset an open draft baseline or recover mutation safety merely by reopening a sheet.
