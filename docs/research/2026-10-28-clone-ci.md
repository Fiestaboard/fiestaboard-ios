# Fresh clone, live/demo schemes and CI

The committed Xcode project is the normal build input. Native development needs macOS, Xcode 27.1+ (Swift 6.4 in the tested toolchain), the iOS SDK and, for UI execution, an installed compatible iOS 26+ Simulator runtime. All four Swift packages use only local package dependencies. Tooling/contract-integrity checks need Python 3.9+ and Git; isolated backend checks additionally need Docker. XcodeGen 2.46.0 is needed only to check or deliberately regenerate the project. CI downloads that exact release and verifies its SHA-256 against the official release asset digest.

## Native onboarding and explicit demo

Open `FiestaBoard.xcodeproj`, select **FiestaBoard**, choose an available iPhone or iPad, and Run. The normal scheme does not enable `--demo`; a clean install starts live onboarding. Existing saved app state may still restore a prior session. Select **FiestaBoard Demo** for the explicit simulation. Every committed demo UI test also launches its application with `--demo`, so test behavior does not depend on the normal launch scheme.

Both schemes profile with Release configuration and an explicitly disabled `--demo` argument, without inheriting demo launch arguments. Archive uses Release and does not persist process launch arguments into the app. The demo flag is a runtime argument, not a distinct binary or release build setting.

```sh
scripts/build-draft.sh simulator
scripts/build-draft.sh simulator demo
scripts/build-draft.sh device
scripts/build-draft.sh archive
python3 scripts/check-project.py
```

These commands build unsigned Simulator/device apps and an unsigned validation archive. They neither install on hardware nor produce a distributable signed archive. For a real iPhone/iPad install, choose your Team in Xcode and use Xcode's normal signing flow. No script selects a Team, changes credentials or global Xcode settings, or regenerates the working project. The first authorized live target is `http://fiestapi.local:4420`; its network reachability, installed version, real authentication and physical output still require separate runtime evidence. Demo acknowledgement is simulated.

`check-project.py` copies source into a temporary directory, excluding `.git`, `.build`, `.reference`, nested worktrees and user Xcode state. It runs XcodeGen there and compares `project.pbxproj` plus all shared schemes. Only `DEVELOPMENT_TEAM` values are normalized for comparison. All original files and local Team values remain byte-for-byte untouched, including on generator failure. Unexpected drift is an error; deliberate generation belongs in an isolated checkout followed by review and preservation of signing edits. The comparison follows [XcodeGen's pinned project specification](https://github.com/yonaskolb/XcodeGen/blob/2.46.0/Docs/ProjectSpec.md).

## Source and isolated backend setup

The authoritative source version/SHA comes from committed `Contracts/snapshot.json`; do not infer it from an installed service. Current target: 10.1.17 at `b5eac069dce10945eac61e1fdadf6ee4a903ba08`. The 10.0.0 baseline is retained under `Contracts/archive/10.0.0`; historical scoped 10.1.7 evidence is not current-version acceptance.

```sh
python3 -m unittest discover -s Tests/Tooling -v
python3 -m unittest discover -s Tests/Contracts -v
python3 scripts/check-contracts.py
task_root="$(python3 -c 'import tempfile; print(tempfile.mkdtemp(prefix="fiestaboard-contracts-"))')"
python3 scripts/bootstrap-contracts.py --destination "$task_root/bootstrap" --build --test
```

The bootstrap initializes a new Git repository, downloads only the exact metadata commit from the public FiestaBoard repository, checks out that SHA detached, and verifies HEAD. Existing destinations are refused. It uses the clean Dockerfile, never the optional local bootstrap tag, then executes boundary tests with the newly built content ID. `bootstrap.json` records the immutable source/image pair. Source-only download omits `--build --test`; a previously built image can be selected explicitly with `--image sha256:... --test`. A failed preparation leaves its disposable directory for diagnosis and does not alter the upstream repository or native project.

Build inputs are `Tests/Integration/Dockerfile`, `dependencies.lock`, the archived backend at that exact SHA and its pinned `outputs.lock.json`. Network is required to download public source, Python 3.14.9 slim, Debian packages, locked PyPI dependencies and pinned output repository trees. The base tag and Debian repositories are not byte-reproducible; a rebuild's image ID can differ. Preserve the produced receipt and regenerated metadata. Docker's ordinary base/layer cache is allowed; no local substrate image/tag is required. Backend imports, exports and tests execute only in the isolated runner's network-disabled, read-only containers with disposable data and without ASGI lifespan/hardware workers. See [the integration guide](../../Tests/Integration/README.md) for direct runner commands and exact coverage limits.

## CI behavior and runner configuration

`.github/workflows/native.yml` runs on pull requests, pushes and manual dispatch. It has read-only repository permission and no deployment/signing/provider secrets.

- Linux: Python tooling tests, contract-checker tests and integrity gate; download the metadata source pin; clean-build a Docker image; execute all boundary tests; regenerate schemas in disposable storage and compare parsed schema JSON with committed schemas. Artifacts include build/test logs, immutable bootstrap receipt and regenerated metadata/schemas.
- macOS: verify Xcode 27.1+, download hash-verified XcodeGen 2.46.0 into runner temp, compare disposable project generation, run all four package suites, and build unsigned Simulator/device targets and a Release archive. Package/cache paths are job-local. Artifacts include package/build logs and the unsigned archive.
- macOS UI runtime: after native checks, create one disposable compatible Simulator per matrix job (iPhone and iPad) from installed iOS 26+ runtimes/device types, boot it, run actual `xcodebuild test` on **FiestaBoard Demo**, collect `.xcresult` and logs, and delete only that job's Simulator. Missing compatible runtimes fail explicitly; a compile-only result cannot satisfy this job.

Hosted Xcode 27.1 availability has not been verified. The default `macos-latest` is a probe, not a compatibility claim. Set repository variable `NATIVE_RUNNER` to a JSON label array for a compatible runner (for example `["self-hosted","macOS","fiestaboard-xcode27"]`), and optionally `NATIVE_DEVELOPER_DIR` to its selected Xcode developer directory. Install a supported iOS Simulator runtime on that runner. Jobs select tools through per-job environment only; they never run `xcode-select --switch`, install global packages, or alter a user's signing Team. Protect self-hosted runners according to the repository's normal contribution policy.
