## DTOs and semantics for native work

Create: `POST /v1/pages` author body, **201 bare Page**, not `{page:…}`. Tested body fields are `name`, `type=template`, `device_type`, `template`, `grid_rows/grid_cols` for panel and an opaque `future_author` object. Flagship geometry is its canonical6×22 family; panel rows/cols are explicit. Returned Page includes identity, revision, `edit_protocol=page-revision-v1`, `document_protocol=page-document-v1`, full author fields/defaults/metadata. Do not build clones from the reduced native Page projection. No idempotency key or client-assigned identity is established here.

Delete: `DELETE /v1/pages/{id}?expected_revision={originalRevision}`, **200**:

```json
{"id":"deleted-id","message":"…","default_page_created":false,"new_page_id":null,"active_page_updated":false,"new_active_page_id":null}
```

Both flags and nullable IDs are always present in captured receipts. `default_page_created=true` means a compatible Welcome was created; it can happen even when other pages exist if an affected board has no compatible survivor. `active_page_updated=true` means saved active references changed. The single replacement/active ID cannot describe arbitrary multi-board changes: explicitly read affected board/library state. Neither flag means output was physically delivered. Refusals use `{detail:string}` at404/409/412; invalid create422 has FastAPI validation detail arrays, including model-validation errors. Preserve status distinction rather than treating every failure as bad input.

The deletion service acquires settings→config→pages→collections→schedules locks, checks the revision, then checks stored references before deleting. Collections, schedules (including disabled), schedule defaults, silence-page configuration and temporary overrides can block removal; active selection is replaceable. Captured runtime guard evidence covers the first three, not every guard branch. Deletion persists removal before creating replacements; this is not proof of a cross-file atomic transaction or rollback on later I/O failure. Replacement creation and active-setting writes can fail after page removal. Native transport loss/unexpected500/malformed success must remain unknown outcome with explicit readback and no automatic replay. Do not refresh the original revision silently to bypass412, and do not interpret a later missing page as proof this particular delete succeeded.

Create has no original page revision: prevent duplicate dispatch and preserve input on unknown outcome. Matching names after readback cannot identify this create uniquely. Candidate operation authorization needs independent review; source schema or existing edit opt-in alone is insufficient evidence to enable create/delete universally.
